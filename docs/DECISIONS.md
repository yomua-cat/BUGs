## #001 — 游戏引擎选型

**日期**：2026-07-18

**决策**：使用 Unity 6 + C# + miniaudio。

**理由**：
- Unity 是唯一被大量专业音游验证的引擎（Cytus II、Arcaea、Phigros、Muse Dash）
- C# 对 AI 友好（AI 代码生成 Top 5 语言），训练数据丰富
- miniaudio（Public Domain）替代 Unity 内置音频，达到 <10ms 延迟
- Unity Personal 完全免费（收入 <$200K）
- 游戏代码（C#）完全开源（MIT），引擎作为免费运行时

**备选方案**：
- Godot 4.7 + C#：开源引擎，但音频延迟在移动端未经验证，无知名音游案例
- Bevy 0.19 + Rust：ECS 架构优秀，但音频延迟无保证，移动端不成熟，Rust AI 支持中等
- Web 方案：移动端性能不足，已排除

**未来影响**：
- 依赖 Unity 引擎更新节奏
- 需维护 miniaudio 的 Unity 集成层
- 社区贡献者需安装 Unity Hub（免费）

## #002 — 模块化架构

**日期**：2026-07-18

**决策**：采用接口驱动的模块化架构。所有模块通过 `core/Interfaces/` 通信。

**理由**：
- 模块损坏时可独立移除，不影响其他模块
- 接口定义是唯一真理源，编译器强制检查一致性
- AI 协作时接口文档防止不一致

**备选方案**：
- 直接引用：简单但耦合严重，模块无法独立移除
- 事件总线：灵活但调试困难，不适合音游的确定性需求

**未来影响**：
- 每个新模块必须先定义接口
- 接口变更需同步更新所有实现

## #003 — 自定义谱面格式

**日期**：2026-07-18

**决策**：使用自定义 BUGs Chart Format，不沿用现有格式。

**理由**：
- 现有格式（osu!、StepMania、BMS）无法表达复杂谱面表演
- 魔改现有格式难度不亚于自定义
- 自定义格式可针对 AI 可读性优化

**备选方案**：
- 沿用 .osu 格式：社区兼容但表达力受限
- 沿用 BMS 格式：适合键盘但不够通用

**未来影响**：
- 需开发谱面编辑器
- 社区需学习新格式
- 格式规范需持续维护
