# 决策记录

## #001 — 游戏引擎选型

**日期**：2026-07-18

**决策**：使用 Unity 6 + C# + miniaudio。

**理由**：
- Unity 是唯一被大量专业音游验证的引擎（Cytus II、Arcaea、Phigros、Muse Dash）
- C# 对 AI 友好（AI 代码生成 Top 5 语言），训练数据丰富
- miniaudio（Public Domain）替代 Unity 内置音频，达到 <10ms 延迟
- Unity Personal 完全免费（收入 <$200K）
- 游戏代码（C#）完全开源（MIT），引擎作为免费运行时

**备选方案**：
- Godot 4.7 + C#：开源引擎，但音频延迟在移动端未经验证，无知名音游案例
- Bevy 0.19 + Rust：ECS 架构优秀，但音频延迟无保证，移动端不成熟，Rust AI 支持中等
- Web 方案：移动端性能不足，已排除

**未来影响**：
- 依赖 Unity 引擎更新节奏
- 需维护 miniaudio 的 Unity 集成层
- 社区贡献者需安装 Unity Hub（免费）

## #002 — 模块化架构

**日期**：2026-07-18

**决策**：采用接口驱动的模块化架构。所有模块通过 `core/Interfaces/` 通信。

**理由**：
- 模块损坏时可独立移除，不影响其他模块
- 接口定义是唯一真理源，编译器强制检查一致性
- AI 协作时接口文档防止不一致

**备选方案**：
- 直接引用：简单但耦合严重，模块无法独立移除
- 事件总线：灵活但调试困难，不适合音游的确定性需求

**未来影响**：
- 每个新模块必须先定义接口
- 接口变更需同步更新所有实现

## #003 — 自定义谱面格式

**日期**：2026-07-18

**决策**：使用自定义 BUGs Chart Format，不沿用现有格式。

**理由**：
- 现有格式（osu!、StepMania、BMS）无法表达复杂谱面表演
- 魔改现有格式难度不亚于自定义
- 自定义格式可针对 AI 可读性优化

**备选方案**：
- 沿用 .osu 格式：社区兼容但表达力受限
- 沿用 BMS 格式：适合键盘但不够通用

**未来影响**：
- 需开发谱面编辑器
- 社区需学习新格式
- 格式规范需持续维护

## #004 — 设计系统先行（Web 原型阶段）

**日期**：2026-07-22

**决策**：在 Unity 实现前，先在 web 端建立完整可复用设计系统（tokens + 组件库 + 展示页），作为 UI 验证和规范来源。

**理由**：
- 项目原则要求 Phase 1 聚焦"把首页变成可复用设计系统"，而非直接建新页面。
- Web 原型迭代快，便于验证视觉语言、组件边界、动效思路。
- 符合"AI 友好"和"文档先行"原则。
- 后期可作为 Unity UI 的参考/移植基础。

**备选方案**：
- 直接在 Unity 里用 UGUI 边做边抽象：风险高，容易产生页面耦合代码。
- 只写文档不实现：无法真正验证可复用性。

**未来影响**：
- 所有新 UI 工作必须引用 `design/system/`。
- 需要后续决定如何把 web 组件映射到 Unity（或重新实现）。
- 设计决策现在有可运行的载体（showcase），便于 review.

## #005 — 判定点替代判定线

**日期**：2026-07-27

**决策**：判定系统从固定判定线改为**判定点**，具备 XY 位置、Z 深度、角度、半径、模式。

**理由**：
- 自由轨道需要判定区跟随轨道移动/旋转
- 允许纯演出用判定点（不产生判定，仅驱动镜头/特效）
- 多判定点支持双轨、分屏、协同玩法
- Z 深度解决渲染排序与景深

**备选方案**：
- 固定判定线 + 轨道偏移：无法表达旋转、缩放、景深
- 判定区跟随 Note：判定时机与视觉分离，容易产生读谱歧义

**未来影响**：
- 谱面格式新增 `judge_points` 数组，Note 引用 `judge_point` id
- 判定接口 `IJudgementSystem` 需支持动态判定点查询
- 编辑器需可视化编辑判定点轨迹

## #006 — Fx 触发器系统（内置模块仅）

**日期**：2026-07-27

**决策**：谱面通过 `fx: { module, params }` 声明触发器，游戏读取调用内置模块，**禁止运行时自定义代码**（MOD 阶段再开放）。

**理由**：
- 安全性：防止恶意谱面执行任意代码
- 确定性：内置模块行为可测试、可审计、可回放
- 性能：模块注册表静态编译，无 JIT/解释器开销
- 维护：模块参数 Schema 固定，文档化容易

**备选方案**：
- Lua/WASM 脚本：灵活但引入安全/性能/调试复杂度
- 表达式求值：表达力不足，无法处理复杂时序

**未来影响**：
- 新增内置模块需：注册表注册 + JSON Schema + 单元测试 + 文档
- MOD 支持时：引入沙箱 WASM 运行时，模块签名验证
- 编辑器需提供模块参数表单自动生成

## #007 — 判定视觉：仅外圆、无全屏默认效果

**日期**：2026-07-27

**决策**：所有判定光效仅描边圆环/弧线（无填充）；默认判定**禁止**全屏效果（闪光、模糊、色调）；附加效果必须通过 Fx 显式声明。

**理由**：
- 连击 Miss 时全屏闪光会遮挡后续 Note，严重影响可读性
- 外圆设计语言统一（呼应 UI 组件描边风格），视觉干扰最小
- Fx 显式化让谱面作者对视觉负责，防止意外遮挡

**备选方案**：
- 全屏淡入淡出：简单但不可控，Miss 连击灾难
- 判定点局部全屏模糊：性能开销大，移动端不稳定

**未来影响**：
- 判定光效预制体统一为 `RingBurst`（Shader Graph 实现描边扩散）
- `screen_flash` 等模块仅供 Fx 显式调用，文档标注"谨慎使用"
- 无障碍模式可一键关闭所有 Fx 视觉效果

## #008 — HUD 极简：仅连击 + 暂停，结算页显示分数/准确率

**日期**：2026-07-27

**决策**：游玩中 HUD 仅保留连击计数（右侧竖排）与暂停菜单；分数、准确率、进度条、波形全部移至结算页。

**理由**：
- 音游核心体验是"看谱面打节奏"，HUD 越少越好
- 连击是即时反馈，分数/准确率是延迟反馈，分离显示符合认知
- 进度条/波形会诱导玩家看进度而非判定点，破坏沉浸

**备选方案**：
- 顶部常驻分数/准确率：传统音游做法，但视觉噪音大
- 可拖拽进度条：这是音游不是播放器，砍掉

**未来影响**：
- `IUIManager` 接口仅需 `ShowCombo`、`ShowPause`、`ShowResult`
- 结算页组件独立开发，复用设计系统 `result` 组件
- 练习模式可单独开启"实时准确率"显示（作为调试选项）

## #009 — 引擎迁移至 Unreal Engine 5.6.1，全流程 opencode 驱动

**日期**：2026-07-28

**决策**：放弃 Unity 6，采用 **Unreal Engine 5.6.1** 作为唯一引擎，全流程由 opencode + Flopperam MCP 驱动，不手写 Blueprint，不打开编辑器 UI。

**理由**：
- Unity 许可模式（座位订阅制、收入门槛强制升级、特定区域合规风险）与项目"开源 MIT + 可选商业化"长期目标冲突
- UE 原生 Quartz + MetaSound + GAS 完美契合节奏游戏核心需求（样本级时钟、参数化音频、Fx 总线），消除 miniaudio 集成维护成本
- 完整 C++ 源码访问权，音频/渲染管线可深度定制，不受引擎更新破坏
- 版税制（前 $1M 免版税）对独立游戏风险更低
- Flopperam MCP 提供 50+ 工具覆盖 Blueprint 全生命周期、UMG、MetaSound、Sequencer、PCG、GAS、运行时验证，opencode 可完全自主驱动
- 5.6.1 为长期支持版本，稳定性与工具链成熟度最佳，Flopperam MCP 官方支持 5.5/5.6/5.7

**备选方案**：
- Unity 2022 LTS + miniaudio：短期交付快，但长期许可不确定性高、音频延迟优化受限
- UE 4.27：Quartz 已完整，但无 MetaSound/GAS/PCG/CommonUI 现代工具链，移动端管线较旧
- UE 5.8.0：版本过新，Flopperam MCP 等工具链未适配

**未来影响**：
- 核心模块需 C++ 重写（约 4 周核心闭环）
- 团队建立 C++/Blueprint/opencode 开发规范
- CI/CD 迁移至 RunUAT + Gauntlet
- 设计系统 Token 映射至 Slate Style / UMG Theme
- 移动端包体裁剪目标 <80MB (Shipping)
